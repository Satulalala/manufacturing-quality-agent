## 1. 目标和取舍

本文将提问中的“dependencies”按前文理解为 **Deep Agents**。

目标是让制造质量 Agent 的多轮条件和工具调用更可靠，并形成可以演示、可以解释的工程案例。保留 Python、LangGraph、Ollama、FastAPI 和 React；借鉴 Deep Agents 的上下文选择和工具组织思想，不迁移到 `deepagents` SDK，不建设通用 Harness。

针对实习准备，不需要把知名项目的能力全部补齐。优先完成现有主流程演示、针对性回归和源码回讲；发现真实边界问题后再改功能。

本计划整体属于 **P1 增强**，不新增实习准备的必修框架；只有核查中确认影响正确性的缺陷才升级为 P0 修复。下文“必要性高”表示本计划内部的优先次序，不代表面试前必须全部完成。

## 3. 最小任务清单

以下 A、B、C 构成建议完成的最小范围。先查现状，再补必要内容；已有行为满足验收时，以验证记录代替重构。

### A. 保护上下文中的必要信息

**必要性：高。** 质量分析不能因历史变长而改变日期、产线、批次或规格。

实施前发现筛选值、问题和工具参数 schema 会被通用字符串裁剪；预算紧张时 schema 还可能退化为仅工具名。现已改为只压缩工具说明文字，完整保留可执行条件和参数 schema。

已实施：

- 明确必要信息：本轮问题的有效输入、当前数据版本与文件身份、完整筛选条件、待补规格、当前可用工具的必要参数约束。
- 日期、批次、产线等业务标识不做静默字符截断；输入过长或必要上下文无法容纳时明确拒绝/要求澄清。
- 优先删旧消息、旧观察和非必要说明；不以“只留下工具名”冒充仍具有完整参数说明的调用上下文。
- 保留现有估算口径并明确标注；字符预算不能声称是精确 tokenizer 计数，也不能据此保证模型窗口绝不会超限。
- 复用已有上下文统计，按需要记录保留/舍弃项；不记录完整生产数据。

预计涉及：`agent/context_manager.py`、必要时 `agent/decision.py`，及现有上下文测试。

验收：

- [x] 压缩长历史后，筛选、版本、待补条件和工具参数 schema 按原值保留。
- [x] 超长标识不会被截成另一个可执行筛选值。
- [x] 预算优先舍弃旧历史和旧证据；工具 schema 完整保留，工具说明只压缩文字。
- [x] 必要信息放不下时 `ContextBuilder` 抛出明确预算错误，决策循环不会调用模型或工具。

### B. 统一工具说明和失败语义

**必要性：中高。** 改善模型选工具和开发者排错，不需要插件平台。

已实施：

- 保留现有 `ToolDefinition` / `ToolRegistry` API；在 `agent/decision.py` 为各任务工具统一写明用途、范围、参数 schema、结果和失败语义。
- 决策循环把领域结果规范为 `success`、`empty`、`no_data`、`needs_input` 或 `error`；明确的 `error` 返回不能再作为成功证据，缺规格会停止并要求补充。
- 知识检索无结果使用 `empty`，不会抹掉同一轮已取得的质量统计；质量统计无匹配记录和只读查询零行则停止后续推断。
- 保留按任务选择工具、参数与范围校验、确定性统计和 64 KB 输出限制；未增加插件、动态依赖解析或工具注册元数据。
- 保留确定性统计、范围校验和输出体积限制；工具结果不能作为新指令执行。

预计涉及：`tools/registry.py`、`agent/decision.py`，必要时受影响的工具适配函数和既有测试。

验收：

- [x] 非法工具和非法参数在执行前被拒绝，缺少必填参数也不会运行 handler。
- [x] 缺 Cpk 规格不会补造；缺少规格、空结果、执行失败有不同状态。
- [x] 模型不能通过工具参数扩大已锁定的数据范围（现有范围校验回归通过）。
- [x] 决策循环测试覆盖工具选择、参数、观察结果和停止状态；真实模型轨迹仍待 Ollama 响应后补充。

**必要性：高。** 实习项目的重点是可证明、可复现、能讲清。

依赖：A、B；先核查已有测试，新增用例只覆盖实际缺口。

已覆盖的小型回归场景：

| 场景 | 应验证的行为 |
|---|---|
| “2026 年 A 线 1 月”→“那 B 线呢” | 年份和月份继承、产线替换 |
| “B 线 7 月和 8 月” | 两个月都进入实际筛选，解释与范围一致 |
| 长历史后再次追问 | 关键条件不被历史压缩丢失 |
| 缺规格的 Cpk 请求 | 澄清，不猜规格、不执行错误计算 |
| 换文件、换版本或换会话 | 历史证据不被当作当前结果直接复用 |
| 工具名或参数非法、无记录、超预算 | 分别给出可识别的拒绝、空结果或停止状态 |

## 4. 可选任务 D：大型工具结果按需读取

**必要性：当前低。** 仅在真实分析遇到结果过大、预算不足或证据摘要丢失时启动。

复用 `ResultStore`，在结果进入下一次模型上下文前保存完整结果，给模型摘要、关键指标和证据 ID。若确需展开，再增加受控的结果读取工具；按当前会话、文件身份/版本和范围校验访问，限制读取字段与返回体积。不得让模型任意读取本机路径，也不把整表重新塞回上下文。

这会影响结果保存时机、工具循环和读取权限，比 A、B 更大，因此不列入实习准备的默认范围。结果体积限制不能直接删除；已有报告和证据格式尽量兼容。

## 5. 暂缓内容

- 完整迁移到 Deep Agents、重写语言或引入第二套运行框架。
- 多 Agent、动态插件安装、技能市场、任意文件系统和 Shell 执行。
- 模型自动总结后直接写长期记忆。
- 为没有外部接入需求的本地函数增加 MCP 服务。
- 新建向量数据库、分布式队列或通用中间件平台。
- 为精确 token 计数引入额外依赖；先保留透明的估算与余量。

这些内容并非永久不需要，而是当前没有充分业务需求来覆盖其维护成本。
