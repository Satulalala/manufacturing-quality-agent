# 制造质量 Agent 独立前端重构实施计划

日期：2026-10-19

状态：实施中。已建立 React/Vite 工作台、FastAPI 接口、持久化运行与数据服务；浏览器体验、真实 Ollama 闭环及未勾选的交互项仍按 [todo.md](./todo.md) 继续验收。

## 1. 产品目标与设计结论

把当前制造质量分析助手改造成以会话为核心的 Agent 工作台。用户通过自然语言发起调查，在同一会话中补充条件、查看执行进度、阅读模型分析，并打开数据、图表和证据继续核查。

采用独立的 React + TypeScript 前端与 FastAPI 接口层。现有 Agent、统计工具、会话存储和 Ollama 集成继续作为业务内核。旧 Streamlit 页面已在新版入口落地后移除，`run_demo.py` 命令行入口保留。

核心完成标准：

1. 用户消息在右，Agent 回复在左；刷新后可恢复会话和已经完成的回答。
2. 左侧既能切换会话，也能以本会话的提问为目录跳转；这两种导航分别呈现。
3. 回复以可读的模型文字分析为主体，图表和原始数据按需打开。
4. 运行时能看到真实阶段与工具状态；模型尚未返回时页面仍可操作。
5. 输入框固定在会话区域底部，支持附件、已选数据上下文、停止操作和补充参数。
6. 数据来源、分析范围、模型解释与规则回退均可辨认；候选因素保持相关线索的表述。

布局规则：

- 顶栏高约 48 px，仅保留会话标题、数据状态、模型状态与设置入口。
- 左栏默认宽约 248 px，可折叠。会话列表与“本会话问题”目录分别折叠和滚动。
- 中间是主要阅读区域，消息正文建议控制在约 720–900 px；用户消息宽度随内容变化。
- 右侧工作区按需打开，建议宽 380–520 px，可拖动调整。空会话默认关闭，避免挤压正文。
- 中间消息区、左侧目录、右侧结果分别滚动；输入框固定在中间区域底部。
- 1280 px 左右的窄桌面使用右侧覆盖面板；手机端使用抽屉，一次聚焦会话或结果。

### 3.2 首次进入与空会话

首屏以输入框和简短提示为中心，提供“使用演示数据”“上传 CSV”和三条真实可执行的问题示例。演示数据明确标识为模拟数据。

数据、记忆、模型配置进入独立管理面板；聊天首页只显示当前会话实际使用的数据标签和必要状态。

## 5. 模型回复与执行过程设计

### 5.1 回复内容

质量分析回复优先包含：当前问题的结论、关键统计依据、候选因素说明和可执行的现场核查建议。对于知识查询、Cpk、SPC 和无数据等任务，采用对应内容结构，不强制套用同一种报告。

已有模型适配器将解释限制为一句、约 70 字。实施时改为适量的短段落，并让输出结构保留正文、引用与生成来源；长度上限和超时设置可配置。统计数字继续来自确定性工具，候选因素不表述为已证实因果。

保留现有证据引用和数字校验；增加段落、编号、时间与单位等用例，避免扩大文本后误判正常格式或放过模型编造数字。

多步工具模式当前在 agent/workflow.py 中将最终说明的 model_fn 置空。实施时需要单独修复该路径：为最终解释预留受限时间预算，模型失败时保留已完成工具结果，并明确标识回退说明。

### 5.2 实时性与诚实反馈

- 首版提供阶段与统计结果的真实事件流：统计完成即可显示“统计已就绪”，继续等待模型解释。
- 当前模型适配器使用整段结构化返回；首版在验证完成后一次显示正文。
- 逐字模型流式输出作为后续专项能力，需要同时调整 Ollama 调用、结构化输出和证据校验；不通过前端延时逐字播放模拟模型实时输出。
- 原始工具调用参数、证据 ID 和诊断信息放在可展开的执行详情中。
- 进度只显示阶段状态和耗时；没有可计算比例的阶段不显示虚构百分比。

## 7. 技术方案与目录

- 前端：React、TypeScript、Vite；样式使用 CSS 变量和组件样式。首版使用 React 状态及少量 Context 管理工作区，不先引入全局状态框架。
- 接口调用：原生 fetch；运行事件使用 EventSource/SSE。开发时由 Vite 代理 /api，发布时前端静态文件与 API 同源。
- 图表：采用 Apache ECharts，按需引入趋势、柱状和分布图等实际使用的模块。表格首版使用语义化表格和服务端分页。
- 服务端：FastAPI + Pydantic DTO + Uvicorn；同步 Agent 放到受控后台执行单元，避免阻塞 HTTP 事件循环。
- 存储：继续使用 SQLite 和本地文件。来源、运行与事件元信息通过增量表或独立应用存储补充，实施前固定迁移方案并保留现有数据。
- 部署：首版单机、单服务实例；同会话一次一个活动运行，进程内有界队列。跨进程任务队列属于后续扩展。

技术资料：[Vite 入门](https://vite.dev/guide/)、[React TypeScript](https://react.dev/learn/typescript)、[FastAPI 流式响应](https://fastapi.tiangolo.com/advanced/stream-data/)、[ECharts 折线图](https://echarts.apache.org/handbook/zh/how-to/chart-types/line/basic-line/)。

## 8. 接口与运行协议草案

统一前缀 /api/v1；接口层输出稳定 DTO，避免把整个检查点或服务器文件路径直接传给浏览器。正式字段在任务 T02 固定。

| 接口 | 用途 |
|---|---|
| GET /health | 应用状态；模型可用性单独返回，探测失败不阻塞页面外壳 |
| GET、POST /sources | 数据源列表、CSV 上传 |
| GET /sources/{id}/preview | 有界分页预览 |
| GET、POST /sessions | 会话列表、绑定数据版本创建会话 |
| GET、PATCH /sessions/{id} | 会话详情、标题更新 |
| GET /sessions/{id}/messages | 分页获取规范化用户消息、Agent 回复和结果引用 |
| POST /sessions/{id}/runs | 提交问题；接受客户端 submission_id，返回 run_id |
| GET /runs/{id} | 运行状态、已完成回复和错误信息 |
| GET /runs/{id}/events | SSE 订阅，支持事件 ID 续传 |
| POST /runs/{id}/cancel | 请求协作取消 |
| GET /runs/{id}/artifacts | 结果引用、图表数据、因素表 |
| GET /sessions/{id}/evidence/{evidence_id} | 绑定会话的证据读取 |
| GET、POST、DELETE /memories… | 已确认记忆的管理；详细路由在 T09 固定 |

消息必须有独立 message_id。task_id 可能因补参继续执行而跨轮复用，不作为唯一消息锚点。历史记录通过稳定的会话、提交和轮次映射生成消息 ID。

运行状态：queued → running → completed / needs_input / failed / cancelled / interrupted。取消中单独显示 cancelling。报告状态 no_data 对应运行完成及报告无匹配数据，二者分开。

事件示例：

~~~json
{
  "event_id": "run_uuid:17",
  "run_id": "run_uuid",
  "type": "statistics.ready",
  "sequence": 17,
  "message_id": "assistant_message_uuid",
  "payload": {"artifact_id": "artifact_uuid"}
}
~~~

事件类型至少包括 run.started、stage.started、stage.completed、statistics.ready、artifact.ready、message.completed、run.failed、run.cancelled。错误向前端提供稳定错误码及可操作说明，详细堆栈进入本地日志。

实现要求：

1. POST 返回运行标识后，页面独立订阅事件；关闭 SSE 连接不会被解释成取消任务。
2. SSE 事件有顺序与有限保留期；断线使用 Last-Event-ID 恢复。事件过期时重新拉取运行快照。
3. 同一 submission_id 的重复请求复用同一运行；同会话同时提交其他运行，首版返回明确的冲突状态。
4. 使用同一适配层关联现有 session_submissions，避免 UI 运行和 Agent 提交各自执行一次。
5. 同步模型调用通常无法即时中断；取消在工具边界和模型超时返回后生效，进入取消流程后不启动后续步骤，迟到结果不追加为正常回复。
6. 服务重启后，活动任务标为 interrupted；已经完成的消息可读。用户显式重试，首版不承诺自动续跑。
7. 进度事件由应用级运行管理器保存；订阅者数量不会触发额外的模型或工具调用。

## 9. 数据、上下文与安全边界

- 上传通过现有 CSV 校验器，并配置文件大小、预览行数和总记录数上限；首版文件大小默认建议 20 MB，可配置。
- 服务端分配数据源 ID 和存储路径；浏览器只传 ID。删除数据源须检查会话引用并给出明确影响说明。
- 单文件会话绑定数据版本，继续沿用现有范围合并逻辑。切换数据版本时创建新会话。
- 补参表单提交到原待办任务；取消待办与停止正在执行的运行使用不同语义。
- 已确认规格和长期偏好保持原有确认、来源、适用范围约束。
- Markdown 渲染关闭任意 HTML，链接限制为允许协议；模型输出和上传内容均视为不可信数据。
- Ollama 地址、密钥、数据库和服务器路径由后端管理。
- 首版默认仅监听本机；对外开放前必须完成用户身份、会话所有权、上传资源归属和访问控制。多人服务不作为本轮完成声明。

## 10. 实施顺序与阶段交付

任务细节、依赖、文件范围与验收标准见同目录 todo.md。默认单 Agent 顺序实施。

| 阶段 | 任务 | 可审阅交付物 |
|---|---|---|
| A：页面方向落地 | T01–T02 | 新布局可交互预览、API 契约；预览数据明确标为演示 |
| B：真实单文件聊天 | T03–T05 | 上传／选择数据、新建会话、真实模型回复、历史恢复 |
| C：运行与结果工作区 | T06–T08 | 真实进度、停止／断线处理、右侧图表与证据 |
| D：现有能力迁移 | T09–T10 | Cpk 补参、长期记忆、多文件比较 |

阶段 A 完成后页面已能用于审阅视觉与交互，但必须标明预览状态。阶段 B 完成后交付第一个真实闭环。阶段 E 的验收通过后再将独立前端设为推荐入口。

## 11. 验收与验证计划

本轮只制定验证计划；正式实施时按任务执行针对性验证。

功能验收：

- 新建会话后发送“分析 2026 年 1 月 A 产线”，真实工具统计与模型解释均可看到。
- 继续发送“换成夜班”，范围合并正确，问题目录可跳到两轮的不同消息。
- 切换会话或刷新后，消息顺序、解释来源、数据版本和结果关联不变。
- 点击历史消息的图表卡片，右侧显示该轮结果，避免显示最新轮的过滤条件。
- Ollama 不可用、超时、无匹配数据、缺参、上传失败均有对应可恢复状态。
- 断线重连和重复发送不会重复运行；停止操作有服务端状态闭环。
- Cpk 单位确认、长期记忆适用范围、多文件独立分析等现有约束仍成立。

验证分层：

1. 后端契约与状态测试：来源校验、消息持久化、幂等、事件顺序、会话隔离、取消和重启中断。
2. 前端行为测试：问题导航、滚动保留、中文输入法、事件重复／乱序、消息复制与面板切换。
3. 构建与类型检查：TypeScript、前端生产构建、Python 接口导入及相关既有业务回归。
4. 浏览器验收：1440、1280、768、390 px；键盘焦点、可访问名称、减弱动画设置。
5. 真实 Ollama 冒烟：至少一次正常解释、一次超时／服务不可用路径；固定响应测试不能替代真实调用验收。

性能验收采用可测指标：本机服务启动后，未调用模型前聊天外壳可交互时间目标不超过 2 秒；在声明过的固定样本数据上至少记录五次测量和机器环境。服务收到运行请求后，目标 500 ms 内出现排队或执行状态。模型生成耗时单独报告，避免与页面加载合并。

## 12. 风险与完成边界

| 风险 | 应对 |
|---|---|
| 只换皮，后端仍返回一条统计句 | T05 同时改回复生成、持久化与渲染，包含多步模式的最终解释 |
| 同步 Agent 阻塞 API 或停止按钮无效 | 有界后台执行、协作取消和真实状态反馈；不承诺即时强杀模型 |
| 旧模型解释或消息 ID 不完整 | 优先从完整提交结果恢复；无法恢复的旧内容明确保留历史摘要 |
| 单文件、多文件上下文混用 | 模式与数据版本显式绑定；比较按源独立运行 |
| 前端直接暴露原始检查点／大表 | DTO 白名单、分页预览、按引用加载结果 |
| 丰富模型文本破坏证据校验 | 与数字、单位和引用用例同步修改；失败回退保留工具结果 |
| SQLite 多线程写冲突 | 明确连接生命周期和写入串行策略；单进程运行，不隐含支持多实例 |
| 迁移提前丢失原有功能 | 现有入口保留至功能对照和验收通过 |

本轮实施完成指：桌面优先、可本机使用的独立前端，覆盖真实聊天、结果审阅和现有主要分析能力。团队协作、云端多租户、模型逐字流式输出和自动恢复正在执行的模型调用进入后续专项。
